# Architecture rules
- Reminder approval links display a read-only page on GET and apply decisions only on POST, because mail scanners must not send or cancel reminders.
- Privileged reminder clients preserve the opaque-key apikey-only fetch handling, because opaque credentials are not bearer JWTs.
- Deleted business records (quotes, invoices, clients, proposals, items, profiles, recurring) are copied to public.deleted_records by a BEFORE DELETE trigger, because account removal cascades and backups only cover ~14 days.
- Shared drafting uses a server-only Responses stream and centrally defined model, reasoning effort and schema configuration, because every document output must use consistent drafting quality without exposing credentials.
- Proposal generation and revision share a dedicated prompt and format-aware validation; explicit communication requests override proposal headings, tone-only revisions inherit the saved document's format, and numbered headings are accepted, because the workspace must honour the requested deliverable on new and saved drafts.
- Proposal preview, download and email attachment use the same generated PDF blob, because clients must receive exactly the document the owner reviewed.
- Idle sign-out tracks last activity in localStorage shared across tabs and sign-in screens reset that clock, because a fresh sign-in must not inherit a stale idle timestamp.
- All app email goes through sendViaResend, which rejects recipient domains that can't receive mail before sending and provider-suppressed addresses right after; callers return RECIPIENT_UNDELIVERABLE and screens show it without falling back to the mail app, because the provider accepts sends it silently drops.
- App monitoring records events in monitor_events and emails the operator once per fingerprint window: the browser reports errors/dead clicks/rage clicks/failed requests/404s, src/server.ts reports server errors and announces each new build on its first request, and an hourly heartbeat backstops page, service and bounce checks; update src/lib/release-notes.ts with each user-visible change so version notices describe it.
